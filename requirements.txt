# Recruiter-Pro - all dependencies
#
#     pip install -r requirements.txt
#
# One file, in three labelled sections: what the API needs to serve requests,
# what training the model additionally needs, and what running the test suite
# additionally needs. The sections are the boundary that used to be three files
# (requirements.txt / -ml.txt / -dev.txt); it is kept here as structure because
# it is genuinely useful to know which group a package belongs to, and which
# ones a deployment could drop.
#
# The cost of one file, stated plainly: installing the API also installs the
# training and test stacks -- xgboost, matplotlib, seaborn, pytest, ruff and the
# rest -- which is a few hundred megabytes a production image does not need. For
# a project run locally and from a clone that is a fair trade for one obvious
# command. If this is ever containerised, the runtime section alone is what the
# image needs.
#
# Every pin below is verified by import count across src/ and scripts/. The file
# this replaced was both incomplete and bloated: it omitted six packages the
# code imports, so a fresh clone raised ImportError on startup, while pinning
# six that nothing imported at all.

# Exact pins, not lower bounds. These four decide whether CI passes, so a
# range makes "correctly formatted" a function of the install date rather than
# of the code: a clean CI clone resolves to the newest release while a
# developer keeps whatever they installed months ago, and the two disagree
# with nobody having changed a line.
#
# That is not hypothetical. `black>=24.0.0` had CI resolve to 26.5.1 against a
# local 25.11.0, and black's stable style changes yearly -- 7 files failed CI
# that were clean locally. `mypy>=1.8.0` was the same trap one major version
# deep: CI would have installed 2.3.1 against a baseline verified on 1.19.0.
#
# The test tools beside them were exact-pinned already; these were the
# inconsistency. Upgrading any of them is now a deliberate commit that shows
# the reformat or the new findings, which is the only way to read them.
black==25.11.0
ruff==0.16.2                 # replaces flake8 + isort; one config, much faster
mypy==1.19.0
types-requests==2.33.0.20260712  # requests ships no stubs; the Ollama provider uses it
